# 量化交易规则结构化分析技能

## 一、技能概述

本技能用于系统性地分析量化交易规则文件（如算法说明书、策略文档、模型逻辑书），按照统一的七维分析框架提取关键信息，并自动生成标准化 PDF 分析报告。支持 Markdown、纯文本、Word 等多种格式的规则文件。

## 二、触发条件

当出现以下任一情况时调用本技能：
- 用户提供量化交易规则文件并要求分析
- 用户要求对交易策略/模型说明书进行结构化拆解
- 用户要求生成量化策略分析报告（PDF）
- 用户提及"分析量化规则""策略评估""交易模型审查"等关键词

## 三、七维分析框架

对每个量化交易规则文件，必须按以下七个维度依次分析并提取信息：

### 维度1：文件基本信息（metadata）
提取以下字段：
- `file_name`: 文件名
- `model_name`: 模型名称（如 V9.3-ST）
- `model_version`: 版本号
- `model_type`: 模型类型（超短线/中长期/波段等）
- `holding_period`: 持有周期
- `target_return`: 目标收益
- `core_principle`: 核心原则（一句话概括）
- `document_scope`: 文档涵盖范围说明

### 维度2：核心交易策略概述（strategy_overview）
提取以下内容：
- `positioning`: 模型定位与设计目标
- `core_factors`: 核心因子/选股维度列表（含权重）
- `scoring_formula`: 评分公式
- `decision_thresholds`: 决策阈值（如评分≥X分→强烈推荐）
- `key_rules`: 核心交易纪律列表

### 维度3：规则逻辑流程图（logic_flow）
提取决策流程的时间序列或逻辑链路，结构化为步骤数组：
```
[
  { "step": 1, "time": "14:30", "action": "暴雨航行检测", "condition": "F91触发条件", "output": "切换极端生存模式" },
  { "step": 2, "time": "14:35", "action": "环境感知", "condition": "S6温度计算", "output": "确定仓位上限" },
  ...
]
```
若文件含完整时间线（如 V9.3-ST 的决策流程全链路），按时间顺序提取；若为逻辑层级（如 V9.3-LT 的选股→评分→建仓→持有→卖出），按逻辑顺序提取。

### 维度4：关键参数说明（key_parameters）
提取所有量化参数，分类整理为表格结构：
- 仓位管理参数（仓位上限、单方向上限、分批建仓比例）
- 风险控制参数（止损线、风险预算、预警阈值）
- 评分参数（各维度权重、子因子权重、评分区间映射）
- 时间参数（买入窗口、卖出窗口、持有周期、信号确认周期）
- 筛选/剔除参数（硬性剔除条件、一票否决条件）

每个参数提取：`参数名 | 取值/规则 | 触发条件 | 数据来源`

### 维度5：潜在风险点分析（risk_analysis）
从以下角度识别风险点，每个风险点含 `风险描述 | 风险等级(高/中/低) | 触发场景 | 影响范围`：
- **参数刚性风险**：固定阈值在极端行情下失效的可能性
- **数据依赖风险**：依赖外部数据源的延迟、缺失、准确性问题
- **逻辑缺口风险**：规则未覆盖的边缘场景（如开盘跌停、停牌）
- **执行风险**：时间窗口过窄导致无法成交、滑点风险
- **集中度风险**：单一因子/板块权重过高
- **黑天鹅风险**：模型无法预测的极端事件
- **过拟合风险**：参数基于历史经验设定，未来可能失效

### 维度6：规则有效性评估（effectiveness_evaluation）
从以下角度评估：
- `strengths`: 规则优势（至少3条）
- `weaknesses`: 规则不足（至少3条）
- `backtesting_status`: 回测验证状态（是否提及历史回测、验证周期）
- `adaptability`: 市场环境适应性（牛市/熊市/震荡市表现预期）
- `completeness`: 规则完整性评分（1-10分，评估是否覆盖完整交易闭环）
- `completeness_reason`: 完整性评分理由

### 维度7：优化建议（optimization_suggestions）
提出可落地的优化建议，每条含 `建议内容 | 优先级(高/中/低) | 预期效果 | 实施难度`：
- 参数优化建议（动态调整、自适应参数）
- 逻辑补强建议（补充缺失规则、边缘场景覆盖）
- 风控增强建议（增加熔断机制、扩大数据源）
- 执行优化建议（时间窗口调整、滑点控制）
- 可扩展性建议（支持更多品种、市场）

## 四、执行流程

本技能支持两种工作模式：**规则分析模式**（分析策略文档）和**实时数据分析模式**（获取最新市场数据）。

### 步骤0（实时数据分析模式）：获取最新市场数据

当需要基于实时数据生成板块分析或走势预测报告时，先调用数据获取模块：

```bash
# 获取单只ETF数据
python ".trae/skills/quant-rule-analyzer/data_fetcher.py" etf 159770

# 获取最新财经新闻
python ".trae/skills/quant-rule-analyzer/data_fetcher.py" news 50
```

数据获取模块 [data_fetcher.py](file:///f:/基金量化模型/Quantification%20Skills/.trae/skills/quant-rule-analyzer/data_fetcher.py) 提供：
- **ETF行情数据**：历史K线（新浪财经API）、最新净值（同花顺API）
- **技术指标计算**：RSI(14)、MA20、乖离率、回撤幅度、量比、F90分类器判定、F73红线检测
- **新闻事件数据**：全球财经快讯（东方财富API），按板块关键词筛选
- **数据缓存**：1小时TTL文件缓存，避免重复请求

### 步骤0B：板块全盘扫描（实时数据分析模式）

板块扫描模块 [sector_scanner.py](file:///f:/基金量化模型/Quantification%20Skills/.trae/skills/quant-rule-analyzer/sector_scanner.py) 支持两种模式：

**全盘扫描模式**：自动扫描全市场1656只ETF，按40个板块分类，按V9.3规则（F90分类器/F73红线）筛选有交易机会的板块，自动生成ST+LT双模型评分报告。
```bash
# 全盘扫描，自动筛选有交易机会的板块（默认排除追涨区）
python ".trae/skills/quant-rule-analyzer/sector_scanner.py" scan --report

# 全盘扫描，显示所有板块（不筛选）
python ".trae/skills/quant-rule-analyzer/sector_scanner.py" scan --all --report

# 全盘扫描，限制最大板块数
python ".trae/skills/quant-rule-analyzer/sector_scanner.py" scan --max 10 --report

# 列出所有可扫描的板块
python ".trae/skills/quant-rule-analyzer/sector_scanner.py" list
```

**指定板块分析模式**：用户指定板块名称，只分析指定板块。
```bash
# 分析指定板块
python ".trae/skills/quant-rule-analyzer/sector_scanner.py" analyze 机器人 创新药 白酒 --report
```

板块扫描流程：
1. 获取全市场ETF列表（同花顺接口，1656只ETF）
2. 按预定义关键词映射表分类到40个板块（机器人/创新药/半导体/军工/光伏等）
3. 为每个板块选择代表ETF（优先预定义代码，否则选增长率最大的）
4. 获取代表ETF的历史K线数据，计算RSI/MA20/乖离率/F90分类等技术指标
5. 按V9.3规则筛选：抄底区（RSI<40+负乖离）优先，排除追涨区
6. 获取板块相关新闻事件
7. 自动生成ST五维评分 + LT六维评分的双模型JSON
8. 调用 generate_sector_report.py 生成PDF报告

数据源说明：
| 数据源 | 接口 | 用途 | 稳定性 |
|--------|------|------|--------|
| 新浪财经 | `money.finance.sina.com.cn` | ETF历史K线 | 高 |
| 同花顺 | `fund_etf_spot_ths` | ETF最新净值 | 高 |
| 东方财富 | `stock_info_global_em` | 财经新闻 | 中 |
| 东方财富 | `fund_etf_hist_em` | ETF K线（备用） | 中（有反爬） |

### 步骤1：读取与预处理规则文件
1. 使用 Read 工具读取规则文件内容
2. 识别文件格式（Markdown/TXT/其他）
3. 提取文档结构（标题层级、表格、代码块）

### 步骤2：按七维框架提取信息
1. 逐维度分析文件内容
2. 将提取结果组织为符合 `analysis_schema.json` 的 JSON 结构
3. 确保所有数值型参数准确无误（权重、阈值、百分比）

### 步骤3：生成分析结果 JSON
将七维分析结果写入临时 JSON 文件，路径：`reports/{model_name}_analysis.json`

JSON 顶层结构：
```json
{
  "metadata": { ... },
  "strategy_overview": { ... },
  "logic_flow": [ ... ],
  "key_parameters": { ... },
  "risk_analysis": [ ... ],
  "effectiveness_evaluation": { ... },
  "optimization_suggestions": [ ... ]
}
```

### 步骤4：生成 PDF 报告
执行以下命令生成 PDF：
```bash
python ".trae/skills/quant-rule-analyzer/generate_report.py" "reports/{model_name}_analysis.json" "reports/{model_name}_分析报告.pdf"
```

### 步骤5：验证输出
1. 确认 PDF 文件已生成且非空
2. 向用户报告生成路径
3. 简要汇报关键发现（3-5条要点）

## 五、多格式适配指南

本技能需适应不同格式的量化交易规则文件：

| 文件格式 | 识别特征 | 提取策略 |
|---------|---------|---------|
| Markdown | `#`/`##` 标题、`\|` 表格 | 按标题层级映射七维，解析表格提取参数 |
| 纯文本 | 无格式标记，靠段落分隔 | 按关键词（"止损""仓位""评分"）定位段落 |
| Word(docx) | 二进制/XML | 若无法直接读取，提示用户转为 Markdown 或 TXT |
| JSON/YAML | 结构化配置 | 直接映射字段到七维框架 |

**通用提取原则**：
- 表格优先：量化规则多以表格呈现参数，优先解析表格
- 数值精确：所有百分比、阈值、权重必须精确提取，不可近似
- 上下文关联：参数需关联其触发条件和执行动作
- 缺失字段处理：若文件未涉及某维度内容，标注"文档未提及"而非留空

## 六、报告输出规范

生成的 PDF 报告必须包含以下章节，顺序固定：

1. **封面页**：报告标题、模型名称、分析日期、分析师（AI）
2. **文件基本信息**：表格呈现元数据
3. **核心交易策略概述**：定位、因子体系、评分公式、决策阈值
4. **规则逻辑流程图**：可视化流程图 + 步骤说明表
5. **关键参数说明**：分类参数表格（仓位/风控/评分/时间/筛选）
6. **潜在风险点分析**：风险清单表格，含等级标识
7. **规则有效性评估**：优势/不足分栏 + 完整性评分
8. **优化建议**：建议清单表格，含优先级
9. **免责声明**：标准风险提示

## 七、质量校验清单

完成分析后，逐项确认：
- [ ] 七个维度均已分析，无遗漏
- [ ] 所有数值参数与原文一致（交叉校验权重和=100%）
- [ ] 流程图步骤逻辑连贯，无断点
- [ ] 风险点至少识别5条，覆盖不同类型
- [ ] 优化建议至少3条，具备可操作性
- [ ] PDF 文件已成功生成
- [ ] 报告排版专业，表格/图表清晰可读
